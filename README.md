# TexasAgent —— 基于视觉大模型的德州扑克智能决策系统

TexasAgent 是一个将视觉大模型（Vision-Language Model, VLM）与大语言模型推理能力（LLM Reasoning）相结合的德州扑克（Texas Hold'em）智能决策系统。项目旨在探索多模态大模型在复杂不完全信息博弈中的决策潜力，构建一个从"看见牌面"到"策略推理"再到"动作输出"的端到端智能体。

## 核心思想

传统德州扑克AI（如基于强化学习的 Pluribus）依赖大量自对弈训练和预定义策略空间，而 TexasAgent 另辟蹊径——利用预训练大模型已有的常识推理能力、模式识别能力和自然语言理解能力，通过视觉输入直接感知牌局状态，进行类人化的推理决策，而不需要大量的领域特定训练。

## 功能特性

- **视觉牌面识别**：使用 VLM（通义千问 qwen3-vl）直接"看懂"牌桌截图，识别手牌、公牌、筹码、位置
- **YOLO 辅助检测**：自训练 YOLO 模型检测时钟标志（判断轮次）、玩家位置、弃牌状态、座位分布
- **蒙特卡洛胜率计算**：基于 treys 库进行 1000 次蒙特卡洛模拟，实时估算手牌胜率
- **三层决策机制**：预过滤层（极速弃牌）→ AI决策层（LLM推理）→ 纠错层（规则修正）
- **多引擎支持**：支持阿里通义千问、DeepSeek、xAI Grok 三大 LLM 引擎，可按圈配置不同引擎
- **对手建模**：基于历史行动分析对手类型（紧凶/松凶/松被动/紧弱），动态调整剥削策略
- **链式思维推理**：6步法分析框架（牌力评估→数学计算→对手分析→位置筹码→策略矩阵→风险控制）
- **可解释决策**：每步决策附带自然语言推理依据，输出胜率、赔率、OUT数等关键参数
- **实时 GUI 叠加**：Tkinter 透明窗口叠加在游戏窗口旁，实时显示决策结果和行动建议
- **语音播报**：决策结果通过 Windows SAPI 语音合成实时播报

### 三大模块

**视觉感知层（VLM Encoding）**
- 使用多模态大模型（通义千问 qwen3-vl-plus/flash）对牌桌截图进行解析
- 自动识别：玩家手牌、公共牌、底池大小、筹码量、玩家位置、行动历史
- YOLO 模型辅助检测时钟标志、弃牌状态、座位分布
- 输出结构化的牌局状态信息

**状态编码层（Context Encoding）**
- 将视觉解析结果转化为结构化的自然语言 Prompt
- 包含：当前局势描述、历史行动轨迹、对手建模提示、风险收益计算
- 支持链式思维（Chain-of-Thought）引导，使推理过程可解释
- 蒙特卡洛胜率、底池赔率、公牌纹理分析、对手类型推断等数学化编码

**推理决策层（LLM Reasoning & Decision）**
- 调用大语言模型（DeepSeek / 通义千问 / Grok）进行策略推理
- 结合博弈论原则（位置优势、底池赔率、手牌范围等）生成决策
- 输出动作：Fold / Check / Call / Bet / Raise / All-in
- 三层决策机制：预过滤 → AI决策 → 纠错修正

## 大模型技术特色

| 技术点 | 应用方式 |
|--------|----------|
| 多模态视觉理解 | VLM 直接"看懂"牌局，无需 OCR+规则解析的传统管线 |
| 链式思维推理（CoT） | 引导模型逐步分析手牌强度、对手范围、赔率计算后再决策 |
| Few-shot 情境学习 | 在 Prompt 中注入经典牌局案例，提升模型策略水平 |
| 可解释性决策 | 大模型不仅输出动作，还输出推理过程，打破传统 AI"黑盒"困境 |
| 零样本泛化能力 | 无需针对特定规则或界面训练，天然适配不同扑克平台 |

## 环境要求

- **操作系统**：Windows 10/11（依赖 win32gui、SAPI 语音等模块）
- **Python**：3.10+
- **GPU**：推荐 NVIDIA CUDA（CPU 也可运行，但 YOLO 推理较慢）
- **游戏客户端**：德州扑克客户端（默认进程名 `Laixi.exe`，可在 `default.py` 中修改）

## 快速开始

### 1. 克隆项目

```bash
git clone https://github.com/feichenxi/TexasAgent.git
cd TexasAgent
```

### 2. 安装依赖

```bash
# 创建虚拟环境
python -m venv venv
venv\Scripts\activate  # Windows

# 安装依赖
pip install -r requirements.txt
```

### 3. 配置 API 密钥

所有模型配置已统一归口到 `model/config.ini`，复制模板并填入你的密钥：

```bash
# 复制配置模板
copy model\config.example.ini model\config.ini

# 编辑 model/config.ini，填入你的 API 密钥
```

也可以使用 `.env` 文件（环境变量优先级更高）：

```bash
copy .env.example .env

# 编辑 .env 文件，填入你的 API 密钥
```

> 需要配置的 API 密钥：
> - **阿里云 DashScope**（通义千问 VLM + LLM）：https://dashscope.console.aliyun.com/apiKey
> - **DeepSeek**（LLM 决策推理）：https://platform.deepseek.com/api_keys
> - **xAI Grok**（LLM 决策推理，可选）：https://console.x.ai/

### 4. 准备游戏客户端

- 启动德州扑克客户端
- 确保窗口可见（不可最小化）
- 默认检测进程名 `Laixi.exe`，如需修改请编辑 `default.py` 中的 `find_poker_window()`

### 5. 运行程序

```bash
python default.py
```

运行后程序会：
1. 检测授权（未配置时自动以本地模式运行）
2. 读取模型配置，显示当前引擎和参数
3. 自动查找游戏窗口并开始检测循环
4. 在游戏窗口旁显示透明 GUI 叠加层，实时展示决策结果

## 配置说明

所有配置集中在 `model/config.ini` 一个文件中，包含以下部分：

| 配置段 | 说明 |
|--------|------|
| `[api_keys]` | 三大模型 API 密钥（阿里/DeepSeek/xAI） |
| `[api_urls]` | 各模型 API 基础地址 |
| `[vision_models]` | 视觉模型名称（VLM 牌面识别） |
| `[language_models]` | 语言模型名称（LLM 决策推理） |
| `[decision]` | 决策参数（阈值、引擎选择、提示词） |
| `[server]` | 服务器/数据库配置（可选） |
| `[misc]` | HuggingFace 镜像等杂项 |

决策引擎选择 `aipa` 参数说明：4个字符分别对应 4 个圈次的引擎，`d`=DeepSeek，`a`=阿里，`x`=xAI。例如 `dddd` 表示全部使用 DeepSeek。

## 决策原理

程序采用三层决策机制：

1. **预过滤层**（极速响应）：当蒙特卡洛胜率低于阈值（默认15%）且处于底牌圈时，自动弃牌或免费看牌，无需调用 LLM
2. **AI 决策层**（LLM 推理）：构建包含牌力、赔率、对手分析、公牌纹理的结构化 Prompt，调用 LLM 输出最优动作
3. **纠错层**（规则修正）：检查 AI 输出是否违反游戏规则（如免费看牌时弃牌），自动修正

数据流示例：
```
截图 → YOLO检测(时钟/位置/弃牌) → VLM识别(手牌/公牌/筹码)
    → 蒙特卡洛胜率计算 → Prompt构建(6步法分析框架)
    → LLM推理决策 → 纠错层校验 → 输出: {"action": "call", "betting": "9.3"}
```

## 研究问题与创新点

- **创新点一**：首次将 VLM+LLM 的级联架构系统性地应用于德州扑克决策任务，替代传统 CV+RL 的技术路线
- **创新点二**：探索大模型在"不完全信息博弈"中的推理边界——当模型无法看到对手底牌时，如何通过语言层面的"心理建模"进行决策
- **创新点三**：构建可解释的 AI 扑克智能体，每一步决策都附带自然语言推理依据，提升人机交互信任度

## 实验与评估

- **基准对比**：与随机策略、简单规则策略、以及开源 GTO 基线进行对比
- **评估指标**：BB/100（每百手大盲注收益）、决策准确率、动作分布合理性
- **消融实验**：对比纯视觉输入 vs 结构化输入 vs VLM+LLM 端到端的效果差异
- **人工评估**：邀请人类扑克玩家对 AI 决策质量进行主观评分

## 注意事项

- 本项目仅适用于 Windows 平台（依赖 win32gui 等模块）
- YOLO 模型文件（`card.pt`、`button.pt`）已包含在仓库中
- 运行时需要游戏窗口保持可见状态
- 建议使用 GPU 加速以获得更好的 YOLO 检测帧率
- API 调用会产生费用，请注意各平台的用量和余额
